# cpsit/myra-web-api 2.0 — design

Status: proposal, to be reviewed before implementation. Becomes the upgrade guide
(`UPGRADE-2.0.md`) once the API is settled.

## Why a 2.0

1.x grew two parallel class families (`WebApi` + endpoints for API v1, `WebApiV2` + `*V2`
endpoints) with different signatures, and left the differences to the consumer:
`CacheClear::clear(string $domain, …)` vs. `CacheClearV2::clear(int $domainId, …)`, the
response content in `list`, `targetObject` or `data`, success as an `error` flag inside an
array, failures as Guzzle exceptions. EXT:myra_cloud_connector therefore detects the API
version by hostname, resolves domain ids itself and reads raw arrays — knowledge that
belongs here, and that nobody could test there.

The Guzzle 7 → 8 upgrade showed the second problem: Guzzle types in the public API
(constructor handlers, `GuzzleException` in signatures) make every Guzzle major a breaking
change for all consumers.

## Facts the design is built on

Captured from the real API (v1 and v2, both auth methods, 2026-10-16):

- **Both auth methods work on both versions**: HMAC signature (API key + secret) and
  Bearer token. Auth and version are independent.
- **One envelope** in both versions: `{error, violationList, warningList, …}`; lists add
  `page`, `count`, `pageSize` (50). Content field: v1 `list` (lists) / `targetObject`
  (writes), v2 `data` (both).
- **Every failure is HTTP 403** (rarely 401), so the status says only "not OK":
  - JSON envelope with `error: true` → rejected request, details in `violationList[]`
    (`propertyPath`, `message`, optional `code` such as `DOMAIN_DOES_NOT_EXIST`, optional
    `translations`).
  - No envelope: wrong credentials (v1: `text/plain` message, v2: empty body), v1 unknown
    domain (empty body), v2 without token (`{"error": "Session has been revoked"}`, a
    string).
- **v2 addresses domains by numeric id** (`/domain/{id}/…`); the name is rejected
  ("The entity does not exist."). v1 uses the name.
- The DNS record and cache clear objects are the same in both versions.

## Layout

```
Myracloud\WebApi\
├── Auth\            Authentication (interface), HmacSignature, BearerToken      shared
├── Http\            Transport: PSR-18 client + PSR-17 factories, Guzzle default  shared
│                    Envelope: parses the response envelope, raises exceptions
├── Exception\       MyraException (interface)                                  shared
│                    ├── RequestRejectedException  (violations)
│                    ├── AccessDeniedException     (credentials, or v1 unknown domain)
│                    └── TransportException        (network, 5xx, invalid JSON)
├── Model\           value objects identical in v1 and v2: DnsRecord, CacheClear,  shared
│                    Domain, Violation, Page<T>
├── Contract\        interfaces for operations both versions offer, e.g.          shared
│                    DnsRecords, CacheClearing — consumers type against these
├── V1\              Client + endpoints for API v1 (base https://api.myracloud.com/{lang}/rapi/)
│   └── Model\       objects only v1 has
└── V2\              Client + endpoints for API v2 (base https://apiv2.myracloud.com/)
    └── Model\       objects only v2 has
```

Rules:

- **Shared vs. version-only is visible in the namespace.** An operation both versions
  offer is a `Contract\` interface, implemented in `V1\` and `V2\`. An operation only one
  version offers exists only in that namespace. Nothing is silently ignored or emulated.
- **Domains are passed by name** in `Contract\`. `V2\` resolves the id itself (paged
  `GET /domains`, cached for the client's lifetime) and additionally offers id-based
  methods.
- **Version and auth are chosen explicitly**, never derived from a hostname:
  `new V1\Client(new HmacSignature($key, $secret))`,
  `new V2\Client(new BearerToken($token))`, any combination allowed; the base URL is an
  optional constructor argument (local emulators, proxies).
- **Typed results.** Every operation returns value objects; fields not modelled stay
  available through `raw()`.
- **Lists are eager.** `list()` fetches all pages and returns all items; `page(n)`
  returns one `Page<T>` for callers that want to page themselves. A lazy generator would
  throw in the middle of the consumer's `foreach`, outside the `try` around the call.
- **No Guzzle in signatures.** The transport takes a PSR-18 `ClientInterface` and PSR-17
  factories; without them it builds Guzzle (^7.8 || ^8). Guzzle runs with
  `http_errors => false`; the envelope decides, and network errors become
  `TransportException`. Consumers catch `MyraException` only.

Sketch:

```php
$client = new V2\Client(new BearerToken($token));        // or V1\Client, or HmacSignature

foreach ($client->dnsRecords()->list('example.com') as $record) {   // Contract\DnsRecords
    if ($record->isActive() && $record->isEnabled()) { … }
}

$client->cacheClear()->clear('example.com', fqdn: 'www.example.com', resource: '/*', recursive: true);
$client->cacheClear()->clearBulk('example.com', 'www.example.com', ['/*.css', '/*.js']);

try { … } catch (RequestRejectedException $e) { $e->violations(); }  // MyraException
```

## Scope and order

All areas 1.x covers, each for v1 and v2: domain, DNS records (incl. load balancing),
subdomain settings, cache settings, cache clear, redirects, IP filter, maintenance, SSL
certificates, statistics, IP ranges (v1 `networks`, v2 `ip-ranges`). v2-only areas
(users, tokens, WAF, tags, waiting room, …) are out of scope unless asked for.

1. **Vertical slice**: Auth, Http, Exception, Envelope, Page, the v2 id resolver; then
   domains, DNS records, cache clear (single + bulk) — tested against the captured
   answers. Review of the public API.
2. **Each further area only after a capture**: one list call and one harmless write per
   version, because the areas do not line up one to one (v1 names vs. v2 `domainId` /
   `vHostName`, v1 "load balance" vs. v2 `dns-records/load-balancing`, …).

## Tests and quality gates

A rewrite is only as trustworthy as its tests, so they are part of every step, not a
final phase. No test touches the network.

- **Unit tests** per component:
  - `Auth\HmacSignature` against fixed test vectors (known key, secret, date, method, path,
    body → known signature), including query strings and empty bodies; `BearerToken`.
  - `Http\Envelope`: every captured answer → the right result or exception
    (success list/write, `error: true` with violations, empty 403, `text/plain` 403,
    401 with `{"error": "…"}`, invalid JSON, 5xx, network failure).
  - Pagination (`Page<T>`, following pages) and the v2 id resolver (paging through
    `/domains`, caching, unknown name).
  - Every endpoint, per version: the exact request it sends (method, URL, query, JSON
    body, auth header) and the value objects it builds from the answer.
- **Contract tests**: one test class per `Contract\` interface, run against `V1\Client`
  and `V2\Client` with the same expectations (data provider over the versions). This is
  the proof that "shared" really behaves the same.
- **Fixtures**: anonymised real answers in `tests/Fixtures/{v1,v2}/<area>/…json`; each
  area gets its fixtures from a capture before it is implemented.
- **Test double**: a small PSR-18 fake client that records requests and replays
  fixtures; the same seam a consumer uses (no Guzzle mock handler in tests).
- **Mutation testing** (Infection) on `Auth`, `Http` and `Exception`: there a weak test is
  dangerous (a signature test that passes for a wrong signature).

Gates (CI, GitHub Actions; all must pass for a release):

- `composer validate --strict`, dependency analysis (declared = used).
- Lint: `php -l` over `src/` and `tests/`, PHP-CS-Fixer (`@PER-CS2.0`, strict types,
  no unused imports) as dry run.
- PHPStan level `max` + strict rules + deprecation rules, **no baseline** (new code).
- PHPUnit with coverage; matrix PHP 8.2–8.5 × Guzzle 7 and 8 (`--prefer-lowest` /
  highest).
- Before tagging: one real smoke call per version × auth method (confirms HMAC on v2).

PHP minimum becomes `^8.2`: 8.1 is end of life (security support ended 2025-12-31), both
connector branches already require `~8.2`+, PHPUnit 11 needs 8.2, and
`#[\SensitiveParameter]` (see Auth) has no effect on 8.1. Projects on 8.1 stay on `^1.2`.

## Auth

- `Authentication::authenticate(RequestInterface): RequestInterface`, called by the
  transport as the last step, on the final request (method, URI, body).
- **Stateless, signed per request.** `HmacSignature` takes the date from a `psr/clock`
  `ClockInterface` on every call (default: own `SystemClock`; tests: a fixed clock for the
  test vectors). 1.x fixed the date in the constructor, so long-lived clients (workers,
  CLI) signed with a stale date. Nothing is cached, so nothing can go stale or needs
  "regenerating".
- **No retry on auth failure.** A 403 cannot tell wrong credentials from a v1 unknown
  domain or a rejected request; a retry would repeat a request that fails, may run writes
  twice, and doubles failed-auth traffic (rate limits / lockout). A wrong host clock fails
  again with a fresh signature too — that is an NTP problem. Fail fast with
  `AccessDeniedException`.
- The body hash covers exactly the bytes sent (`(string) $body`); 1.x trimmed the body and
  read it with `getContents()` without rewinding. The v2 spec hashes the untrimmed body.
- Secrets: `#[\SensitiveParameter]` on the constructor parameter (not in stack traces),
  stored inside a `\SensitiveParameterValue` (PHP 8.2): verified hidden from `var_dump`,
  `print_r`, `var_export`, `(array)` and `json_encode`, and `serialize()` throws — so no
  secret lands in a log, cache or session by accident. A hand-written `__debugInfo()`
  would not cover `var_export` or the array cast. Classes are `final readonly`.
- Empty key, secret or token (after trimming) → `Exception\InvalidArgumentException`
  (a `MyraException`) at construction — an unset configuration fails loudly instead of
  sending unauthenticated requests (cf. connector bug 2 in `testing-2026-10-16.md`).
- The v2 spec (`openapi.json`, `info.description` §2.1.2) documents the same HMAC algorithm
  as v1, with the request path from `/` as URI. Bearer tokens are static; a revoked token
  needs a new one from the user, the library cannot refresh it.

Notes from setting the gates up:

- PHPStan does not report syntax newer than the minimum (e.g. PHP 8.4 `new Foo()->bar()`),
  and ddev runs 8.5 — only the CI row on PHP 8.2 (lint + tests) guards the minimum.
- Infection runs without its PHPStan integration: it starts PHPStan under the memory limit
  of the initial test run, PHPStan crashes, and a crash counts as a killed mutant (it hid a
  real escaped mutant). Equivalent mutants are avoided in the code (named arguments
  instead of meaningless literals), not ignored.
- HMAC test vectors come from the spec's openssl script, not from this implementation.

## Http

- `Transport` (internal) builds the request (`Accept` + `Content-Type: application/json`,
  JSON body with unescaped slashes, query per RFC 3986), authenticates it last, sends it
  through PSR-18 and hands the response to `Envelope::parse()`.
- Default client: Guzzle with `connect_timeout` 10 s and `timeout` 30 s — Guzzle's own
  default is no timeout, which would let a hanging API block e.g. a TYPO3 cache flush.
  Guzzle's PSR-18 `sendRequest()` already disables `http_errors` and redirects. Other
  values: pass your own PSR-18 client.
- `Envelope::parse()` follows the captures: `error: true` → `RequestRejectedException`
  (also on 2xx), `error` as string → `AccessDeniedException`, no envelope + 401/403 →
  `AccessDeniedException` (quoting at most 200 bytes of a text body), 5xx / other status /
  not a JSON object → `TransportException`. A 2xx envelope without `error` is accepted.
- `JsonObject` (internal): typed field access; a missing or mistyped field is a
  `TransportException` naming the field by path (`list[0].upstreamOptions.weight`),
  never its value.
- Exception messages contain method and URI, never the request object (it carries the
  `Authorization` header).

## Removed in 2.0

- `WebApi`, `WebApiV2`, all `Endpoint\*` classes, `Middleware\Signature` (now
  `Auth\HmacSignature`).
- The CLI (`bin/`, `Command\*`) and with it `symfony/console`, `symfony/yaml` and
  `s1lentium/iptools` (only `WhitelistToolCommand` used it).
- Guzzle types in signatures; `GuzzleException` is no longer thrown to consumers.

Consumers that need the old API stay on `^1.2`; a `1.x` branch keeps receiving fixes.

## Test data

The repository is public. Fixtures recorded from real accounts are anonymised before they
are committed: domains → `example.com`, IPs → documentation ranges (`192.0.2.0/24`,
`2001:db8::/32`), ids, organisation ids and CNAMEs → made-up values. Real origin addresses
behind Myra would allow bypassing the CDN and its WAF.

## Open

- HMAC against v2: works (verified with Postman), and the v2 spec documents the same
  algorithm (signed path = the request's path and query, no `/{lang}/rapi` prefix). Still
  confirm with one real v2 request signed by **this package's** `HmacSignature` before the
  release — that tests our implementation, not Myra.
- Contract tests cover all four combinations version × auth, not only the captured two.
- v2 paging (resolved by capture 16): `?page=N`, echoed as `page`; past the last page
  `data` is empty; `count` is the total number of hits, as in v1 (page in the path there,
  `/dnsRecords/{domain}/{page}`). The spec documents no paging parameter.
