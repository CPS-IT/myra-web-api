# cpsit/myra-web-api 2.0 — design

Status: proposal, to be reviewed before implementation. Becomes the upgrade guide
(`UPGRADE-2.0.md`) once the API is settled.

## Why a 2.0

1.x grew two parallel class families (`WebApi` + endpoints for API v1, `WebApiV2` + `*V2`
endpoints) with different signatures, and left the differences to the consumer:
`CacheClear::clear(string $domain, …)` vs. `CacheClearV2::clear(int $domainId, …)`, the
response content in `list`, `targetObject` or `data`, success as an `error` flag inside an
array, failures as Guzzle exceptions. EXT:myra_cloud_connector therefore detects the API
version by hostname, resolves domain ids itself and reads raw arrays — knowledge that
belongs here, and that nobody could test there.

The Guzzle 7 → 8 upgrade showed the second problem: Guzzle types in the public API
(constructor handlers, `GuzzleException` in signatures) make every Guzzle major a breaking
change for all consumers.

## Facts the design is built on

Captured from the real API (v1 and v2, both auth methods, 2026-10-16):

- **Both auth methods work on both versions**: HMAC signature (API key + secret) and
  Bearer token. Auth and version are independent.
- **One envelope** in both versions: `{error, violationList, warningList, …}`; lists add
  `page`, `count`, `pageSize` (50). Content field: v1 `list` (lists) / `targetObject`
  (writes), v2 `data` (both).
- **Every failure is HTTP 403** (rarely 401), so the status says only "not OK":
  - JSON envelope with `error: true` → rejected request, details in `violationList[]`
    (`propertyPath`, `message`, optional `code` such as `DOMAIN_DOES_NOT_EXIST`, optional
    `translations`).
  - No envelope: wrong credentials (v1: `text/plain` message, v2: empty body), v1 unknown
    domain (empty body), v2 without token (`{"error": "Session has been revoked"}`, a
    string).
- **v2 addresses domains by numeric id** (`/domain/{id}/…`); the name is rejected
  ("The entity does not exist."). v1 uses the name.
- The DNS record and cache clear objects are the same in both versions.

## Layout

```
Myracloud\WebApi\
├── Auth\            Authentication (interface), HmacSignature, BearerToken      shared
├── Http\            Transport: PSR-18 client + PSR-17 factories, Guzzle default  shared
│                    Envelope: parses the response envelope, raises exceptions
├── Exception\       MyraException (interface)                                  shared
│                    ├── RequestRejectedException  (violations)
│                    ├── AccessDeniedException     (credentials, or v1 unknown domain)
│                    └── TransportException        (network, 5xx, invalid JSON)
├── Model\           value objects identical in v1 and v2: DnsRecord, CacheClear,  shared
│                    Domain, Violation, Page<T>
├── Contract\        interfaces for operations both versions offer, e.g.          shared
│                    DnsRecords, CacheClearing — consumers type against these
├── V1\              Client + endpoints for API v1 (base https://api.myracloud.com/{lang}/rapi/)
│   └── Model\       objects only v1 has
└── V2\              Client + endpoints for API v2 (base https://apiv2.myracloud.com/)
    └── Model\       objects only v2 has
```

Rules:

- **Shared vs. version-only is visible in the namespace.** An operation both versions
  offer is a `Contract\` interface, implemented in `V1\` and `V2\`. An operation only one
  version offers exists only in that namespace. Nothing is silently ignored or emulated.
- **Domains are passed by name** in `Contract\`. `V2\` resolves the id itself (paged
  `GET /domains`, cached for the client's lifetime) and additionally offers id-based
  methods.
- **Version and auth are chosen explicitly**, never derived from a hostname:
  `new V1\Client(new HmacSignature($key, $secret))`,
  `new V2\Client(new BearerToken($token))`, any combination allowed; the base URL is an
  optional constructor argument (local emulators, proxies).
- **Typed results.** Every operation returns value objects; fields not modelled stay
  available through `raw()`.
- **Lists are eager.** `list()` fetches all pages and returns all items; `page(n)`
  returns one `Page<T>` for callers that want to page themselves. A lazy generator would
  throw in the middle of the consumer's `foreach`, outside the `try` around the call.
- **No Guzzle in signatures.** The transport takes a PSR-18 `ClientInterface` and PSR-17
  factories; without them it builds Guzzle (^7.8 || ^8). Guzzle runs with
  `http_errors => false`; the envelope decides, and network errors become
  `TransportException`. Consumers catch `MyraException` only.

Sketch:

```php
$client = new V2\Client(new BearerToken($token));        // or V1\Client, or HmacSignature

foreach ($client->dnsRecords()->list('example.com') as $record) {   // Contract\DnsRecords
    if ($record->isActive() && $record->isEnabled()) { … }
}

$client->cacheClear()->clear('example.com', fqdn: 'www.example.com', resource: '/*', recursive: true);
$client->cacheClear()->clearBulk('example.com', 'www.example.com', ['/*.css', '/*.js']);

try { … } catch (RequestRejectedException $e) { $e->violations(); }  // MyraException
```

## Scope and order

**The complete API of both versions** (decided 2026-10-16, replacing "the areas of 1.x,
v2-only only if asked"): v1 ≈ 43 operations in 17 areas, v2 175 operations in 35 tags —
218 operations in 25 areas, tracked one by one in `docs/api-surface.md`. Shared areas get a
`Contract\` interface; version-only areas live only in `V1\` / `V2\`.

1. **Vertical slice** (done): Auth, Http, Exception, Envelope, Page, the v2 id resolver;
   domains, DNS records, cache clear.
2. **Each further area only after its reads are captured** — `tests/Smoke/capture.php`
   (GET only, anonymised in memory, never raw on disk). Order: the areas 1.x covered (shared,
   the connector needs them), then v1-only rate limit, then the v2-only areas. Redirects
   first: shared, per vHost in v2, with a create → delete cycle — it sets the pattern for
   vHost addressing and writes.
3. **Writes** are captured by the user in Postman (no scripted writes against the account).
   Writes without a harmless test (domains, users, tokens, API keys, SSL, verification,
   waiting room, replication DNS, passwords) are implemented from the manual/spec with exact
   request-shape tests and labelled *write unverified* until captured.
4. v1 writes: PUT creates, POST updates, DELETE carries a body; updates (and some deletes)
   need `id` + `modified` (optimistic locking) — so update/delete take the object read
   before, not an id.

## Tests and quality gates

A rewrite is only as trustworthy as its tests, so they are part of every step, not a
final phase. No test touches the network.

- **Unit tests** per component:
  - `Auth\HmacSignature` against fixed test vectors (known key, secret, date, method, path,
    body → known signature), including query strings and empty bodies; `BearerToken`.
  - `Http\Envelope`: every captured answer → the right result or exception
    (success list/write, `error: true` with violations, empty 403, `text/plain` 403,
    401 with `{"error": "…"}`, invalid JSON, 5xx, network failure).
  - Pagination (`Page<T>`, following pages) and the v2 id resolver (paging through
    `/domains`, caching, unknown name).
  - Every endpoint, per version: the exact request it sends (method, URL, query, JSON
    body, auth header) and the value objects it builds from the answer.
- **Contract tests**: one test class per `Contract\` interface, run against `V1\Client`
  and `V2\Client` with the same expectations (data provider over the versions). This is
  the proof that "shared" really behaves the same.
- **Fixtures**: anonymised real answers in `tests/Fixtures/{v1,v2}/<area>/…json`; each
  area gets its fixtures from a capture before it is implemented.
- **Test double**: a small PSR-18 fake client that records requests and replays
  fixtures; the same seam a consumer uses (no Guzzle mock handler in tests).
- **Mutation testing** (Infection) on `Auth`, `Http` and `Exception`: there a weak test is
  dangerous (a signature test that passes for a wrong signature).

Gates (CI, GitHub Actions; all must pass for a release):

- `composer validate --strict`, dependency analysis (declared = used).
- Lint: `php -l` over `src/` and `tests/`, PHP-CS-Fixer (`@PER-CS2.0`, strict types,
  no unused imports) as dry run.
- PHPStan level `max` + strict rules + deprecation rules, **no baseline** (new code).
- PHPUnit with coverage; matrix PHP 8.2–8.5 × Guzzle 7 and 8 (`--prefer-lowest` /
  highest).
- Before tagging: `tests/Smoke/run.php` — real read-only calls per version × auth method.

PHP minimum becomes `^8.2`: 8.1 is end of life (security support ended 2025-12-31), both
connector branches already require `~8.2`+, PHPUnit 11 needs 8.2, and
`#[\SensitiveParameter]` (see Auth) has no effect on 8.1. Projects on 8.1 stay on `^1.2`.

## Auth

- `Authentication::authenticate(RequestInterface): RequestInterface`, called by the
  transport as the last step, on the final request (method, URI, body).
- **Stateless, signed per request.** `HmacSignature` takes the date from a `psr/clock`
  `ClockInterface` on every call (default: own `SystemClock`; tests: a fixed clock for the
  test vectors). 1.x fixed the date in the constructor, so long-lived clients (workers,
  CLI) signed with a stale date. Nothing is cached, so nothing can go stale or needs
  "regenerating".
- **No retry on auth failure.** A 403 cannot tell wrong credentials from a v1 unknown
  domain or a rejected request; a retry would repeat a request that fails, may run writes
  twice, and doubles failed-auth traffic (rate limits / lockout). A wrong host clock fails
  again with a fresh signature too — that is an NTP problem. Fail fast with
  `AccessDeniedException`.
- The body hash covers exactly the bytes sent (`(string) $body`); 1.x trimmed the body and
  read it with `getContents()` without rewinding. The v2 spec hashes the untrimmed body.
- Secrets: `#[\SensitiveParameter]` on the constructor parameter (not in stack traces),
  stored inside a `\SensitiveParameterValue` (PHP 8.2): verified hidden from `var_dump`,
  `print_r`, `var_export`, `(array)` and `json_encode`, and `serialize()` throws — so no
  secret lands in a log, cache or session by accident. A hand-written `__debugInfo()`
  would not cover `var_export` or the array cast. Classes are `final readonly`.
- Empty key, secret or token (after trimming) → `Exception\InvalidArgumentException`
  (a `MyraException`) at construction — an unset configuration fails loudly instead of
  sending unauthenticated requests (cf. connector bug 2 in `testing-2026-10-16.md`).
- The v2 spec (`openapi.json`, `info.description` §2.1.2) documents the same HMAC algorithm
  as v1, with the request path from `/` as URI. Bearer tokens are static; a revoked token
  needs a new one from the user, the library cannot refresh it.

Notes from setting the gates up:

- PHPStan does not report syntax newer than the minimum (e.g. PHP 8.4 `new Foo()->bar()`),
  and ddev runs 8.5 — only the CI row on PHP 8.2 (lint + tests) guards the minimum.
- Infection runs without its PHPStan integration: it starts PHPStan under the memory limit
  of the initial test run, PHPStan crashes, and a crash counts as a killed mutant (it hid a
  real escaped mutant). Equivalent mutants are avoided in the code (named arguments
  instead of meaningless literals), not ignored.
- HMAC test vectors come from the spec's openssl script, not from this implementation.

## Http

- `Transport` (internal) builds the request (`Accept` + `Content-Type: application/json`,
  JSON body with unescaped slashes, query per RFC 3986), authenticates it last, sends it
  through PSR-18 and hands the response to `Envelope::parse()`.
- Default client: Guzzle with `connect_timeout` 10 s and `timeout` 30 s — Guzzle's own
  default is no timeout, which would let a hanging API block e.g. a TYPO3 cache flush.
  Guzzle's PSR-18 `sendRequest()` already disables `http_errors` and redirects. Other
  values: pass your own PSR-18 client.
- `Envelope::parse()` follows the captures: `error: true` → `RequestRejectedException`
  (also on 2xx), `error` as string → `AccessDeniedException`, no envelope + 401/403 →
  `AccessDeniedException` (quoting at most 200 bytes of a text body), 5xx / other status /
  not a JSON object → `TransportException`. A 2xx envelope without `error` is accepted.
- `JsonObject` (internal): typed field access; a missing or mistyped field is a
  `TransportException` naming the field by path (`list[0].upstreamOptions.weight`),
  never its value.
- Exception messages contain method and URI, never the request object (it carries the
  `Authorization` header).

## Vertical slice: domains, DNS records, cache clear

- `Contract\Client` (`domains()`, `dnsRecords()`, `cacheClear()`) is implemented by
  `V1\Client` and `V2\Client`. Contract interfaces are for type hints; methods may be added
  in minor releases, so implementing them outside the package is not covered by the
  compatibility promise (that is what keeps e.g. a later `iterate()` non-breaking).
- `V1\Client($auth, language: 'en'|'de', baseUri: scheme+host)` — `/{language}/rapi` is
  always appended, so an emulator serves the real paths. `V2\Client($auth, baseUri)`.
- `Page<T>`: `items()`, `page()`, `pageSize()`, `total()` (Myra's `count`, the total hits —
  named `total` because `count` reads like "items on this page"), `hasNext()` =
  `page ≥ 1 and page × pageSize < total`. Eager `list()` stops at the last page, at an empty
  page, when an answer is not the requested page, and when all `total` entries are there. The
  first version stopped only at the last or an empty page — and looped endlessly on v2 error
  pages, which answer *unpaged* (`page: 0`, `pageSize: 10^16`, the same entries for every
  `?page`; captured). Page numbers < 1 are rejected before any request.
- Domain names: case and a trailing dot are ignored (`DomainName::normalize`), in v1 too,
  so both versions accept the same input.
- `V2\DomainIdResolver`: reads `/domains` only as far as needed, remembers every name it
  saw for the client's lifetime; once all pages are read an unknown name fails without
  another request → `DomainNotFoundException` (v2 only; v1 answers an unknown domain with
  the same empty 403 as wrong credentials → `AccessDeniedException`).
- `cacheClear()->clear()` / `clearBulk()` return `list<CacheClear>`, not one object: per
  the v1 manual (§10.2.2) a clear without `fqdn` answers one object per active subdomain.
  `fqdn` is required for now (only that case is captured); allowing `null` later is
  non-breaking. Resources must start with `/` (they are path patterns); a bulk needs a
  non-empty list of strings.
- Models expose only what both versions send and a consumer needs, as required fields
  (`DnsRecord`: id, name, recordType, value, ttl, active, enabled; optional
  `alternativeCname`); everything else through `raw()`. Public constructors, so consumers
  can build test data.
- Contract tests (`tests/Contract`) run the same expectations against v1 and v2, each with
  HMAC and with a token; the fixtures are one account seen through both versions (same
  six DNS records).
- v1 domains (captures 17/18): the same `DomainVO` objects as v2, field by field and with
  the same ids — the manual (§5.2.1) is off here (shows `paused`/`pausedUntil`, lacks
  `permissions`/`verified`). Trust captures over the manual too.
- PHPUnit 11 has no `#[CoversNamespace]` and ignores unknown attributes silently — only
  PHPStan reported it. Coverage metadata is `#[CoversClass]` / `#[UsesClass]`; a coverage
  run (Xdebug) with `beStrictAboutCoverageMetadata` reports missing ones as risky.

## Area pattern (set by redirects)

Every further area follows it, so it is written down once:

- **Addressing.** Areas configured per vhost take only the fully qualified vhost
  (`redirects()->list('www.example.com')`, the apex is `example.com`): v1 accepts a
  subdomain where the manual says `{domain}` and filters by it (captures 19/20); v2 needs
  domain id + `vHostName` — `DomainIdResolver::resolveHost()` finds the zone as the longest
  domain name the host equals or ends with (reads the domain list once). A host of no zone →
  `DomainNotFoundException`; a vhost that does not exist → v2 rejects it ("The entity does not
  exist.", capture 24), v1 answers an empty list (redirects) or HTTP 500 (cache settings,
  maintenance, subdomain settings: `TransportException`).
- **One immutable model per resource** with public constructor (new object: no `id`),
  `with…()` methods and `raw()`. `create()` takes a new object, `update()` / `delete()` the
  object read before — its `id` and `modified` are the optimistic lock (`Model\Persisted`
  guards before anything is sent). `modified` is kept as the exact string Myra sent:
  re-formatting it (`+0100` vs `+01:00`) could break the lock.
- **Enum-like fields are strings with class constants**, not PHP enums: a value Myra adds
  later must not break every consumer's reads.
- v1: `PUT` creates, `POST` updates, `DELETE` with `{id, modified}`; answer in `targetObject`.
  v2: `POST` creates, `PUT …/{id}` updates, `DELETE …/{id}` ("only a 200") — an empty 2xx is a
  success without content. Single objects come as one-element lists (`JsonObject::first()`).
- Version-only operations live only on the version class (`V2\Redirects::get()`).
- Until a write is captured, its tests use the manual/spec examples, labelled as such, and
  the emulator echoes it (listed as assumed in its docblock).
- **Writes are captured by `tests/Smoke/write.php`** (decided 2026-10-16, after reviewing the
  risk with the user): only harmless probes — e.g. a *disabled* redirect of the exact path
  `/__probe__/redirect` — on an unused domain passed as `--domain` (MYRA_DOMAIN is refused),
  on one active, editable vhost of it; `WriteGuard` (unit-tested) refuses every write outside
  the probed area before it is sent; everything created is deleted in `finally` and verified
  gone. Areas whose writes can disturb a site (maintenance, subdomain settings, SSL, error
  pages) are asked about first; domains, users, tokens, API keys, verification are never
  probed.
- Captured for DNS records (81–97): same write pattern and lock as the vhost areas, but per
  domain (zone): `dnsRecords()->create($domain, $record)`. An update sends the **complete record
  as read** with the changes on top (`DnsRecord::toJson()` merges `raw`), so fields not modelled
  (SRV port/weight, CAA, endpoints, …) survive whatever Myra does with missing fields — the
  captured request bodies match byte for byte. Load balancing is not an area of its own: v1
  `dnsRecords?loadbalancer=true&recordTypes=A,AAAA,CNAME` and v2 `/load-balancing` list records
  with `upstreamOptions` (a versioned object of its own); changing them works through the
  normal `update()` in both versions (captured), while v2 `PUT …/{id}/load-balancing` answered
  HTTP 500 for the inactive probe record with both bodies the spec allows — kept as
  `V2\DnsRecords::updateLoadBalancing()`, labelled unverified. A TXT record answers a
  *partial* UpstreamOptionsVO (backup, down): parsed as null, kept in `raw()` — a record must
  stay readable whatever its extras look like (that partial object first broke reading the
  probe's answer and so its cleanup; the probe record was removed by hand, see the log).
- Captured for maintenance (98–113), probed with a page for 2099 (v2 also `active: false`; the
  probe deletes at once and aborts if Myra reports it active — a maintenance whose period has
  begun takes the vhost offline immediately): same pattern and lock, complete-object updates;
  v1 deletes with `{id, fqdn}` as the manual says; v2 create answers **200** (not 201); Myra
  stores the instant but returns it in its own offset (sent `00:00+0000`, read `01:00+0100`) —
  compare as instants, not strings. v2 adds the domain-wide list (`presentAndFuture`), get by
  id and `V2\MaintenanceTemplates` (stored HTML, no effect).
- Captured for error pages (114–126), probed with a page for a code the vhost had none for (413):
  no per-object writes — `set($domain, $html, ['www.example.com' => [413]])` creates or replaces
  the pages of a selection, `delete()` takes a selection; supported codes 400, 404, 405, 413,
  429, 500, 502, 503, 504, 9999 (blocked requests). v1 lists group by subdomain
  (`{subDomainName, error: {code: ErrorPageVO}}`, pageSize 10), v2 lists flat and **unpaged**;
  lists carry no content, `get()` does (v1 `errorpage/{id}` answers in `list`). v2 adds
  `grouped()`.
- Captured for IP ranges (127–131), account-wide and read only: **the versions list different
  sets** — v1 `networks` only the enabled ranges, v2 `ip-ranges` all of them (also 15 disabled
  ones with `validTo` in the past; same objects and ids). `list()` / `page()` pass on what the
  version returns (filtering v2 silently would hide data v2 offers); the contract adds
  `active()` (enabled only), identical in both versions — the one to build a firewall
  allowlist from, so nobody opens expired ranges by switching to v2. Both page by query
  (`?page=&pageSize=`), v1 too although the manual shows none; `networks/{page}` answers 403.
- Captured for statistics (132–146) with `tests/Smoke/statistics.php`: reads sent as POST, so
  a probe of its own whose guard allows exactly the statistic paths; stricter anonymisation —
  every metric number except 0 replaced, URLs → `/path-N`, lists cut to 3 (a site's traffic is
  not for a public repo). `statistic/query` is **the same in v1 and v2** — same body, same
  `StatisticVO`, **no envelope** (no `error` key): `Contract\Statistics::query()`. A result
  set's shape depends on type AND source: `stats` → min/max/sum/avg, but response_codes /
  country_codes → those per key (incl. `Other`); `histogram` → `{value}` per bucket keyed by
  milliseconds (the manual says min/max/avg/sum). Result sets are read by accessor
  (`stats()`, `statsByKey()`, `histogram()`), not parsed up front. An unknown source: v1
  HTTP 500, empty body. v2 adds the dashboard statistics (`V2\Statistics`): period as Unix
  **seconds** in the path, answers in **milliseconds**; bare JSON lists without envelope
  (status codes, top/cached URLs, world map → `Transport::sendList()`), **`null` for none**;
  graphs with `max`/`sum` 0 although the points have values; `data: null` for a host without
  requests; totals and graphs kept as maps by Myra's names (dozens, Myra adds new ones — typed
  getters would freeze them). Status codes come for every code Myra knows, 0 when none.
  Failures are envelopes as usual (unknown domain → 400 INTERNAL_ERROR, unknown chart → 403).
- Captured for subdomains, domain by id and verification (147–157), v2 only: `V2\Subdomains`
  lists the vhosts of the account or of one domain (no objectType; `label` is the FQDN). The
  account list **ignores paging** (asked for page 2 of size 2, it answers all 7 with
  `page: 2`) — so it has no `page()`, and `Page::collect` stops because everything has
  arrived; per domain, paging works. `V2\Domains::get(int)` takes the id because `Domains`
  feeds the id resolver itself. `V2\DomainVerifications`: `status()` captured; `check()` from
  the spec (*unverified*; on a verified domain the spec promises 409
  `DOMAIN_VERIFICATION_ALREADY_VERIFIED` — a harmless capture, not done without asking).
  Verifying by hand and foreign descendants are for Myra agents only (403) and not offered.
- Captured for SSL certificates (158–164): v1 and v2 send identical `SslCertVO` lists, **per
  domain** — v1 given a subdomain lists the domain's certificates (unlike the vhost areas).
  `Contract\SslCertificates`: list/page, `upload()` and `update()` (*writes unverified*: a
  certificate goes live, no harmless probe). An upload is its own input object
  (`SslCertificateUpload`: PEM, private key, password — held in `SensitiveParameterValue`, so
  they never show in dumps or traces; Myra never returns them). `update()` sends the manual's
  minimal body (id, modified, subdomains, new intermediates if any) — not the object as read,
  which carries `password: ""` and intermediates without PEM. v2 adds get, delete (only for a
  certificate assigned to no subdomain, spec) and Myra's TLS presets (`configurations()`). v1
  has no delete: Myra removes certificates unassigned for a week. Writes go to
  `/domain/{id}/certificates` (no `/ssl`, as in the spec), reads to `…/ssl/certificates`. The
  anonymiser now fakes fingerprints and serial numbers as hex pairs (they came out as IPv6).
- Captured for the WAF catalogue (165–169), v2 only, the same for every account:
  `V2\Waf` — conditions, actions, countries as models, matching types and action values as
  the maps Myra sends. Countries come **unpaged** (250 entries, pageSize 50). The anonymiser
  redacted most labels (country names, action names) — public data, but the fixtures keep only
  the shapes. WAF *rules* are still open: the account has none (no shape captured).
- Captured for users and organisation (170–185), v2 only, sensitive: anonymised in memory and
  every value reviewed by eye — which caught what the leak check cannot see: login locations
  (`latitude`/`longitude` of activities) and ids of real objects under unusual keys
  (`objectInstance`, `scopes`); the anonymiser now covers both. `V2\Users` (me, users, groups,
  members, permissions, API keys, tokens, activities) and `V2\Organization` (contacts, contact
  types, notes). API keys come with the public key only, tokens without their value. The own
  permissions come unpaged (pageSize = count); activities page (176 entries) and are offered
  page by page only — a log, not a list to collect.
- WAF rule write probe (186, approved by the user): a *disabled* rule matching only the exact
  path `/__probe__/waf` with the action `log` (processNext on), on the unused domain — Myra
  answered **HTTP 403 with an empty body**, although the user holds `DomainWafRule CREATE`;
  nothing was created (verified by the cleanup). The `DomainVO.permissions` of both domains of
  the account carry no WAF key (SslCert, ErrorPage, WaitingRoom, … are there) — consistent
  with WAF not being available to them, not a proof.
  Not retried with variations (each try is a write on a live account). For it the `WriteGuard`
  learned exact `METHOD /path` writes, and the update/delete of a probe object is allowed only
  once that object exists (`allowing()`), never for an object that existed before.
- Users, groups and permissions — writes from the spec, *unverified* (never probed: these are
  on the never-probe list). Unlike the area pattern, creates take their fields as arguments
  (`create($email, …)`, `createGroup($name, $parent)`, `grantToUser(…)`): the read models have
  required ids, and inventing "new object" variants for shapes nobody has seen Myra accept
  would only look verified. Updates take the object read before, changed with with…(). A user
  update sends the role fields (`roles`, `rootGroupRoles`, `isIndirectCustomer`) **exactly as
  read** — whether Myra keeps an omitted one is unknown, and losing it could cost administrator
  rights, also one's own; the warning is on the public method. A group update needs `parent`
  (spec), which the captured GroupVO lacks — so the caller passes it.
- **Two probe leftovers, both removed by hand the same day** (and why it cannot recur):
  the first DNS probe could not read its own answer (a TXT record's partial `upstreamOptions`
  broke the model) and so could not clean up — one inactive TXT `__probe__` record stayed until
  deleted with raw requests; the first error page probe hung in the endless paging loop above
  and was stopped before its cleanup — the probe page (413) was deleted afterwards. Fixes: the
  models read partial extras leniently, paging has several stop conditions, and the
  `RecordingClient` stops a run after 400 requests.
- An `error` **string** means access denied only with HTTP 401/403 (captured: 401 "Session has
  been revoked"); with any other status it is a rejection whose violation code is the string —
  the spec answers a user delete with 409 `{"error": "user_assigned_to_groups"}` (not captured).
- A 5xx answer with an envelope keeps Myra's message in the `TransportException`
  ("… Myra says: An internal error occurred. Reference: …" — the reference helps Myra's
  support).
- Captured for subdomain settings (69–80): no list resource — `targetObject` holds five
  inheritance layers (most general first, the vhost's own last), `domain` the vhost's own
  settings, `parent` the inherited ones (the manual's structure is outdated); `?flat` answers
  the merged map without envelope, in v2 too (not in the spec). v2 GET answers in
  `targetObject`, v2 POST in `data`. Values differ by version: v1 sends numbers as strings.
  Settings are a map (`Model\Settings`: `own()`, `inherited()`, `value()`), not typed fields —
  94 names of mixed types, and Myra adds new ones. No `modified`, no lock. `update()` posts and
  reads again; whether Myra replaces or merges the own settings is NOT verified (only an
  unchanged write was probed, on a vhost without own settings), so the docblock tells callers
  to always send the complete own settings — correct either way. `get()` / `effective()` are
  `@phpstan-impure`. A subdomain that is no vhost: v1 HTTP 500, v2 403.
- Captured for the IP filter (38–55): same pattern and lock; the v2 CSV **import** answers
  HTTP 201 with `error: false` even when lines were skipped (the spec says `true`) — the
  skipped lines come as violations, so `V2\IpFilters::import()` returns them (`list<Violation>`,
  empty = all imported) instead of throwing; `expireDate` exists only when set (via import;
  setting it through create/update is not captured). Non-JSON bodies and answers go through
  `Transport::sendRaw()` / `fetchText()`; HMAC signs the request's own `Content-Type` (the
  spec's script has it as a variable; a CSV import signed over `text/csv` works against Myra).
- Captured for redirects (25–37): the lock is enforced in both versions — a stale `modified`
  is rejected with v1 HTTP **200** + `error: true`, v2 HTTP **400**; v2 create = 201, delete =
  204 empty; the v1 delete answers JSON declared as `text/html` (the parser goes by the body,
  not the header); `enabled: false` is honoured by both versions.

## Emulator and integration tests

- `tests/Emulator/index.php` emulates v1 and v2 for `php -S`. Answers are fixtures (real,
  anonymised), including the failures as Myra sends them. **Assumed, not captured** —
  answered like the captured neighbour, listed in the emulator's docblock: v1 without
  header / with a wrong token, v2 with wrong HMAC credentials,
  v1 unknown domain on `PUT cacheClear`, v1 `recursive` not boolean, paging, the cache
  clear echo and the 404 "Not emulated". The integration test asserts exact messages only
  for the captured combinations. Authentication is recomputed from the spec, not with this package's
  `HmacSignature`, so it checks the package instead of agreeing with it. Call log
  (JSON lines): method, URI, auth, `auth_ok`, body, `Content-Length` vs. received bytes.
- Why in the repository and not only in ddev: CI runs the same integration tests, and the
  emulator can replace the v1-only one in the sbb project (its answers were made up and
  differed from Myra: envelope instead of `text/plain` 403, 400 instead of 403, no paging).
- `tests/Integration` (suite `integration`) starts the emulator on a free port and runs
  both clients through the **default Guzzle client** over real HTTP, all four version ×
  auth combinations, pages of 2. The proxy barrier exempts only `127.0.0.1`.
- Local manual use: `.ddev/config.myra.yaml` (local, like all of `.ddev/`) runs it as a
  `web_extra_daemon` on `https://myra-web-api.ddev.site:8446` — no extra container.

## Removed in 2.0

- `WebApi`, `WebApiV2`, all `Endpoint\*` classes, `Middleware\Signature` (now
  `Auth\HmacSignature`).
- The CLI (`bin/`, `Command\*`) and with it `symfony/console`, `symfony/yaml` and
  `s1lentium/iptools` (only `WhitelistToolCommand` used it).
- Guzzle types in signatures; `GuzzleException` is no longer thrown to consumers.

Consumers that need the old API stay on `^1.2`; a `1.x` branch keeps receiving fixes.

## Test data

The repository is public. Fixtures recorded from real accounts are anonymised before they
are committed: domains → `example.com`, IPs → documentation ranges (`192.0.2.0/24`,
`2001:db8::/32`), ids, organisation ids and CNAMEs → made-up values. Real origin addresses
behind Myra would allow bypassing the CDN and its WAF.
