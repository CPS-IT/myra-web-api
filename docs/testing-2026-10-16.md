# Verification log 2026-10-16

What was tested around 1.2.0 and the connector fixes, how, and what it showed. Kept because
2.0 must not lose any of it.

## Setup

- A TYPO3 13.4 installation (ddev) with `cpsit/myra-cloud-connector` (branch
  `feature/guzzle-8-3.x`) and `cpsit/myra-web-api` 1.2.0.
- A **local Myra API v1 emulator** (PHP built-in server in a ddev service): recomputes the
  v1 HMAC signature exactly like `Middleware\Signature` (403 on mismatch, like Myra), answers
  `dnsRecords` and `cacheClear`, logs every call with method, path, body, `Content-Length`
  vs. received bytes, and `signature_ok`. v1 only: the 1.x connector picks v2 only for the
  hostname `apiv2.myracloud.com`.
- Real API answers: see `captures/`.

## 1.2.0 (Guzzle 7 and 8)

| Check | Result |
|---|---|
| 1.1.0 against Guzzle 8 (mock responses) | fatal on the first call: `Utils::jsonDecode()` removed, `TransferException` needs a request |
| 1.2.0 against Guzzle 8.2.0 + symfony/console 7.4 (mock responses) | 9/9: JSON → array, v1 signature headers, URI, 204 and invalid JSON → `UnexpectedResponseException` (a `GuzzleException`), 500 → `ServerException`, v2 Bearer header, 9 console commands register |
| Real HTTP through the connector, Guzzle 8.2.0 and 7.15.5 | identical calls, signatures valid, bodies complete (`Content-Length` = received) |
| Error path (wrong secret → 403), Guzzle 7 | caught, editor sees the error notification, no fatal |

A suspicion that Guzzle 8 would send an exhausted request body (the signature middleware
reads it with `getContents()` without rewinding) was **disproved** by the emulator's byte
count.

## Connector (EXT:myra_cloud_connector) — found and fixed with the emulator

1. Typed extension settings (`onlyLive: 0` from YAML/settings.php) → `TypeError` that killed
   every cache flush, including `typo3 cache:flush`.
2. An empty `myra_token` disabled the extension silently, although v1 needs only key +
   secret.
3. Purges went to **every** active DNS record of the Myra domain (other sites and
   environments, e.g. staging purged production). Now only the hosts of the affected TYPO3
   site; "clear all" = all sites of the instance.
4. A failed DNS record lookup was cached as an empty list → no purges until expiry.
5. Recursive clears sent `/` and `/folder` instead of the patterns `/*` and `/folder/*`
   (Myra matches `resource` as a pattern) → "clear all" and folder clears reached almost
   nothing.
6. File and folder clears from the backend crashed (HTTP 500): runtime cache identifier
   built from `1:/path`.

Final behaviour in the emulator log (Guzzle 8.2.0, web-api 1.2.0):

| Action | Sent |
|---|---|
| Page purge | 1 × `PUT cacheClear`, site host, `/page-path/`, not recursive |
| Page purge, other language | the translated path, same host |
| Editor saves content on a page | that page only (needs the page to have been rendered and cached once) |
| Clear all pages | `/*` recursive, the instance's hosts only |
| Clear all files | `/fileadmin/*`, `/_assets/*`, `/typo3/*`, `/typo3temp/*` recursive |
| Folder | `/fileadmin/<folder>/*` recursive |
| Single file | its exact path |

## What 2.0 has to keep

- The v1 HMAC algorithm byte for byte (signing string `md5(body)#METHOD#path?query#application/json#date`,
  date key `HMAC-SHA256(date, "MYRA" . secret)`, signing key
  `HMAC-SHA256("myra-api-request", dateKey)`, signature `base64(HMAC-SHA512(signingString, signingKey))`,
  empty body → `d41d8cd98f00b204e9800998ecf8427e`, header `Authorization: MYRA {key}:{signature}`).
- Pattern semantics for recursive clears (consumer responsibility, but document it).
- Every capture case in `captures/` as a test.
